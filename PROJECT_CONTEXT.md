# Атласум: контекст проекта

Этот файл предназначен для новых чатов по проекту. Перед началом работы прочитайте его вместе с `README.md`, а затем изучите только относящиеся к задаче файлы. Не меняйте продуктовые требования и существующие данные без отдельного запроса пользователя.

## Кратко

**Атласум** - русскоязычная учебная веб-платформа для подготовки к экзаменам и самостоятельной практики. Пользователь выбирает дисциплину, проходит экзамен, тренажёр, мини-игры или путь «Нашелинго», получает отчёт с объяснениями и сохраняет свой прогресс.

Текущая версия в коде: **v2.81** (`src/lib/version.ts`, `package.json`).

Основные дисциплины:

- `it-design` - информационные технологии и компьютерная графика;
- `management` - менеджмент;
- `economics` - экономика;
- `english` - английский язык, включая отдельные темы по временам.

## Технологии и структура

| Область | Решение | Главные файлы |
| --- | --- | --- |
| Клиент | React 19, TypeScript, Vite, React Router, React Query, Tailwind, Framer Motion | `src/` |
| Локальный API | Express + TypeScript | `server/app.ts`, `server/index.ts` |
| Локальная БД | SQLite через Prisma | `prisma/schema.prisma`, `prisma/dev.db` |
| Production-синхронизация | Netlify Functions + Netlify Blobs | `netlify/functions/` |
| Контент | Генерируемый JSON и TypeScript-каталоги | `data/questions.json`, `server/*-content.ts` |
| Общие типы | TypeScript-типы, контракты попыток и вопросов | `shared/types.ts` |

Важные каталоги:

- `src/pages/` - страницы приложения;
- `src/components/` - общие визуальные и интерактивные компоненты;
- `src/lib/` - клиентская логика: авторизация, тема, чат, запросы на сообщения, прогресс Нашелинго, цвета интерфейса;
- `server/content.ts` - общий каталог дисциплин, тем, режимов, мини-игр и генерация метаданных;
- `server/question-bank.ts` - выборка вопросов и защита от повторов;
- `server/english-content.ts`, `server/english-tenses-content.ts` - английский контент;
- `shared/question-uniqueness.ts`, `shared/question-text.ts` - нормализация текста и уникальность вопросов;
- `netlify/functions/` - production API для аккаунтов, рейтинга, сообщений, уведомлений, дуэлей, обращений и прогресса.

## Учебная логика

### Вопросы и отчёты

- У каждого вопроса есть стабильный `id`, тема, сложность, тип, варианты, правильный ответ, объяснение, источник и теги. См. `shared/types.ts`.
- Вопросы бывают `single`, `multiple`, `trueFalse`, `matching`, `sequence`, `fill`, `imageChoice`, `scenario`.
- Вопросы **не должны повторяться внутри одного теста**. Проверяйте и генератор, и отображение при переходах назад/вперёд.
- При отправке попытки обязательно передаётся `questionSnapshot`: отчёт обязан строиться по той версии вопроса, которую пользователь реально увидел. Нельзя сопоставлять текст одного вопроса с вариантами другого.
- Пояснения в отчёте должны быть конкретными, связанными именно с вопросом. Не использовать шаблонные фразы вида «выделите ключевой признак понятия». Для обычных вопросов достаточно 1-2 предложений; для упражнений по английскому возможны несколько информативных предложений.
- В тексте отчёта не показывать технические идентификаторы вопросов вроде `q-english-tense-...` или «Задание 20» без необходимости.

### Критичное замечание к качеству банка вопросов

Пользователь отметил, что заметная часть вопросов построена слишком абстрактно, не имеет ясной связи с вариантами ответа или выглядит как текст, сгенерированный нейросетью. Это относится прежде всего к ИТ-вопросам: формулировка «протокол веба» неоднозначна, поскольку существуют HTTP, TCP, UDP, DNS, QUIC и другие протоколы разных уровней и назначений.

При доработке банка:

- формулируйте проверяемое понятие точно: указывайте протокол, его уровень/контекст и задачу, например «Какой прикладной протокол обычно используют для обмена HTTP-запросами и ответами?»;
- не создавайте варианты, которые относятся к другому уровню сети или не являются равноправными ответами, если вопрос этого явно не объясняет;
- не сводите HTTP к «протоколу передачи HTML»: это прикладной протокол обмена сообщениями, который используется не только браузерами и HTML;
- проверяйте каждую пару «вопрос - варианты - правильный ответ - пояснение» как единое задание, а не как независимые строки;
- заменяйте шаблонные или неестественные формулировки на короткий человеческий язык с понятным учебным контекстом.

Это задача контентного аудита, а не только UI: перед изменением нужно определить перечень спорных тем и переработать вопросы с сохранением уникальности их `id` там, где это возможно.

### Экзамен и практика

- Экзамен: **30 вопросов**, лимит **45 минут** для всех дисциплин. По окончании времени показать итоговое окно с количеством отвеченных и правильных ответов, переходом в отчёт и работой над ошибками.
- Свободная практика и тематические тесты запускаются только явной кнопкой «Начать», не автоматически.
- В тренировочном режиме можно выбирать несколько обычных тем **или** несколько слабых тем, но не оба типа одновременно.
- При переключении на экзамен сбрасывать выбор тем и слабых тем, показывать экзаменационное состояние как недоступное для редактирования.
- Мини-игра «Кто быстрее» использует таймер 3 минуты.

### Английский язык

- Базовая экзаменационная структура: 45 минут, 30 вопросов. Категории и веса: лексика - 2 балла, грамматика - 4, сопоставления и порядок фраз - 8.
- Темы времён английского языка разделены отдельно. Обычный тест по одному времени: теория перед первым уровнем и не более 10 вопросов в тренажёре; в Нашелинго - шесть вопросов на уровень.
- «Все времена английского языка (только экзамен)» остаётся доступной в экзамене, но **не показывается в Нашелинго**. Если пользователь выбрал просто «Экзамен», вопросы из этой специальной темы не должны попадать в банк без явного выбора темы.
- Для английского нужны разные активности: выбор формы, вставка пропусков, ручной ввод, перевод с русского на английский и обратно, составление фразы перетаскиванием слов. Регистр, варианты `don't`/`dont`/`do not` и другие допустимые формы должны обрабатываться разумно.
- Проверяйте русско-английские переводы и грамматические маркеры времени: `already`, `yet`, `just`, `once`, `this year` и т. п. В русском предложении не должны пропадать слова, от которых зависит выбор времени.
- Имена людей во всех заданиях по английскому пишутся латиницей, даже если перевод идёт на русский.
- Вопросы и варианты ответа не должны раскрывать перевод правильного варианта. Нажатие на слова в самом задании показывает перевод над выбранным словом; это обязано работать на компьютере, телефоне и планшете.

### Нашелинго

- Нашелинго - отдельный маршрут обучения в стиле коротких уроков, а не копия обычного тренажёра.
- Дисциплина содержит разделы, в них темы, у каждой темы пять последовательных уровней по шесть вопросов. Следующий уровень открывается только после предыдущего.
- Уровень считается пройденным при результате не менее **4/6**.
- Теория темы состоит из пяти уникальных экранов, обязательна перед первым уровнем, но после прохождения доступна для повторного чтения. Теория и уровни должны синхронизироваться между устройствами.
- Процент раздела и темы зависит от пройденных уровней. Склонения числительных на русском обязательны: «1 тема», «2 темы», «5 тем», «24 темы».
- В Нашелинго скрыта работа над ошибками; после урока остаётся отчёт.

### Игры и 1 на 1

- Показывайте только те мини-игры, для которых у дисциплины есть подходящие вопросы.
- Приглашение на 1 на 1: хост видит оверлей ожидания; когда соперник принял, оба сразу попадают в одну сессию с вопросами и таймером. Нельзя требовать от хоста «продолжить игру».
- Если соперник не вошёл за 30 секунд или хост отменил приглашение, игра отменяется тихо: оверлей закрывается, уведомление об отмене не создаётся.
- Принятые приглашения исчезают из уведомлений. Состояние дуэли, сообщений и уведомлений должно обновляться без ручного обновления страницы.

## Профили, сообщества и безопасность

- Локальная сессия хранится в `localStorage`; production-аккаунты и общие данные синхронизируются через Netlify Functions/Blobs.
- Ник уникален без учёта регистра. Нельзя регистрировать имя, которое уже существует. Администратор - `lonexnesss` (`src/lib/permissions.ts`).
- Только `lonexnesss` может написать любому пользователю без предварительного запроса.
- Для остальных личная переписка требует запроса доступа. Пока запрос ожидает решения, показывать «Дождитесь решения», не позволять отправлять его повторно. При отказе показать понятное сообщение и не давать спамить запросами.
- В диалоге каждый участник может заблокировать другого. Заблокировавший также не может писать, пока не разблокирует пользователя.
- Забаненный пользователь видит только экран бана и выход. Бан постоянный, с причиной; забаненные исчезают из рейтинга и сообщений. Список банов и разблокировка доступны только администратору; список ограничен 10 строками с прокруткой.
- Список чатов сортируется по последнему сообщению. Видны последнее сообщение, автор последнего сообщения и индикатор непрочитанного. Нельзя написать самому себе.

## Визуальные и адаптивные требования

- Продукт называется **Атласум**. Не возвращать прежнее название `Examora` в title, Open Graph, favicon, метаданных или интерфейсе.
- Основной текущий стиль - тёмная тема с поддержкой светлой; выбранный пользователем интерфейсный цвет (`ocean`, `pink`, `violet`, `mint`, `amber`, `coral`) применяется во **всём интерфейсе** и в обеих темах. Выбор дисциплины не должен менять цвет интерфейса.
- Стили версий: `src/design-2.2.css` и `src/design-2.7.css`. Флаги находятся в `src/lib/design-version.ts`; сейчас слой 2.7 выключен (`DESIGN_V27_ENABLED = false`). Не включать его и не удалять как «мёртвый код» без запроса - это точка отката дизайна.
- Не допускать обрезания текста, накладок, дрожания вёрстки и переноса одной буквы в кнопках. Особенно проверить iPhone 11 (390 px) и iPhone 14 Pro Max (430 px), а также desktop.
- На iOS все поля ввода на мобильных должны иметь размер шрифта не менее `16px`, иначе браузер увеличивает экран.
- Заголовок, мобильная навигация, чаты, реакции, эмодзи-панель, аватарное меню и счётчики непрочитанного требуют отдельной проверки на desktop и mobile.
- В сообщениях нужны контрастные пузырьки и белый текст на тёмных исходящих сообщениях. Реакции и выбор эмодзи открываются поверх чата/сообщения, не двигают контент, закрываются по клику вне меню и не перекрывают кнопку открытия.
- На главной нет лидерборда: рейтинг открывается отдельной кнопкой. «Предложить улучшение» не выводится как отдельный блок главной страницы.

## XP, уровни и звания

- Монеты отключены из продуктового сценария; используйте только XP.
- Счётчики больших значений выводятся компактно: `1k`, `1.3k` и т. п.
- В рейтинге показываются уровень и звание пользователя.
- Настроена 30-уровневая система со своими званиями; требования XP растут постепенно (не фиксированное значение). При изменении формулы сохраняйте обратную совместимость уже накопленного XP.

## API и данные

Локальный Express API:

- `GET /api/meta` - метаданные, профиль, темы, прогресс, попытки, достижения;
- `GET/POST/PUT/DELETE /api/questions` - каталог вопросов и админ-операции;
- `POST /api/tests/generate` - получить тест;
- `POST /api/tests/submit` - отправить попытку с `questionSnapshot`;
- `GET /api/reviews` - данные повторения;
- `POST /api/nashelingo/theory/complete` - сохранить теорию;
- `GET /api/ranking`, `GET /api/profile`, `GET /api/health`.

Production Functions:

- `auth.mts` - регистрация, вход, сессии, аватар, цвет интерфейса, бан;
- `leaderboard.mts` - общий рейтинг;
- `messages.mts`, `message-access.mts` - чаты, разрешения и блокировки;
- `nashelingo-progress.mts` - синхронизация теории и уровней;
- `duels.mts` - 1 на 1;
- `bugs.mts`, `reviews.mts` - обращения и отзывы.

При переносе на новый Netlify Site данные не появляются сами: каждый сайт имеет отдельное Blobs-хранилище. Для миграции используется `scripts/migrate-netlify-blobs.mjs`; подробные безопасные команды есть в `README.md`.

## Как использовать этот файл в новом чате

При первом сообщении приложите или укажите `PROJECT_CONTEXT.md`, затем сформулируйте конкретную задачу. Для визуальной ошибки добавьте скриншот, устройство/разрешение и путь страницы. Для контентной ошибки добавьте дисциплину, тему, точный текст вопроса или его `id`.
